{{ SITE_NAME }} applies layered security controls across authentication, infrastructure, and operations. This Security Center summarizes buyer-relevant practices — not a certification claim (we do not assert SOC 2 here).

Security Center map

  • Privacy Center — policies and data requests
  • System status — live component probes
  • Business continuity — backups without overclaim
  • Enterprise readiness — live vs roadmap controls
  • Documentation — operator and API notes

Authentication & access

  • Email verification required for customer portal access.
  • Staff accounts require two-factor authentication (TOTP + backup codes).
  • Login rate limiting, account lockout, and session tracking/revocation.
  • Role-based access control for staff and operations areas.

Application security

  • CSRF protection on authenticated and public forms.
  • Security headers including CSP without inline scripts, HSTS (production), and secure cookies.
  • Audit logging for authentication events, payments, demo submissions, and admin changes.
  • Public endpoint rate limits for checkout, contact, newsletter, and webhooks.
  • Demo forms protected with honeypot and per-IP rate limits.

Data protection

  • Passwords stored using Django's secure hashing framework.
  • Production deployments use PostgreSQL (with SSL mode and statement timeout settings), Redis, TLS, and restricted server access.
  • Payment card data is handled by configured payment gateways — not stored on this marketing platform.
  • Payment proof uploads are served through authenticated downloads, not public media URLs.

Encryption & transport

  • HTTPS/TLS for production traffic.
  • Secure cookie flags in production settings.

Responsible disclosure

Report suspected vulnerabilities to {{ SUPPORT_EMAIL|default:"security@zreta.com" }}. Include steps to reproduce and impact assessment. We do not operate a paid bug bounty unless separately announced.
